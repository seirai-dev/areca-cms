# Open issues (w07: SDK reference pages)

- cli: Node version floor. `packages/site-sdk/package.json` says `engines.node >=22.6.0`, but native TypeScript config import for `manifest push` and `manifest pull` may need Node 22.18+ or 23.6+ without a flag. Page states only the engine floor and the `tsx` fallback named in the error (evidence: packages/site-sdk/package.json, packages/site-sdk/src/load-config.ts).
- field-types: `image` field picker. The Library accepts PDFs (ALLOWED_MIMES includes `application/pdf`), and the page says the value may be any Library file. Not confirmed whether the image picker lists PDFs (evidence: apps/cms/src/server/assets/index.ts, apps/cms/src/features/editor/fields/image-well.tsx).
- field-types: `reference` `collection`. The manifest schema marks `collection` optional, but the write path rejects a reference with no collection. Page says the CMS refuses to save without it (evidence: apps/cms/src/routes/api/sites/manifest.ts, apps/cms/src/server/content/validation.ts `validateReferences`).
- field-types: route pattern. The UI hint says `$slug` is replaced by each entry's slug. The notes say the route must include `$slug`, but no validation rule was found in the manifest schema. Page says to use `$slug` and does not claim it is enforced (evidence: apps/cms/src/routes/api/sites/manifest.ts, apps/cms/messages/en.json `content_schema_route_hint`).
- http-api: preview response headers. `docs/API.md` says preview responses carry `Cache-Control: no-store` and `X-Robots-Tag: noindex, nofollow`. The CMS route sends `Cache-Control: no-store, private` and `X-Robots-Tag: noindex`. Page follows the code. The docs owner of `docs/API.md` (being retired) should not be the source for this (evidence: apps/cms/src/routes/api/sites/preview.ts, docs/API.md).
