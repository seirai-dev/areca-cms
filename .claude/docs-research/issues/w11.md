# Open issues: w11 (security section)

- index: The brief asks for "private-by-default media", but the code serves every Library upload without authentication. The page documents the public behavior. Confirm the intended policy and whether a private-media feature is planned (evidence: apps/cms/src/routes/api/assets/file/$prefix/$filename.ts, docs/DEPLOYMENT.md media privacy section)
- index and two-factor-and-step-up: Provider (GitHub, Google, Discord, Microsoft) sessions count as fresh for the 10-minute step-up window without an authenticator code, and an agency admin can use admin actions with a provider session. This is a security decision to confirm or change (evidence: apps/cms/src/server/security/step-up.ts assertFreshSession, apps/cms/src/lib/session.server.ts requireAgencyAdmin, apps/cms/src/lib/auth.ts)
- two-factor-and-step-up: Turning two-factor off as an agency admin is not blocked in the UI; enforcement happens on the next admin call (evidence: apps/cms/src/features/account/two-factor-section.tsx, apps/cms/src/lib/session.server.ts assertAdminMfa). Page documents the current behavior.
- two-factor-and-step-up: Whether "New backup codes" invalidates the previous set (evidence: better-auth two-factor plugin, not verified in code)
- two-factor-and-step-up: Recovery path when an agency admin loses the device and all backup codes (no UI or server path found for another admin to reset a user's two-factor) (evidence: apps/cms/src/server/fn/me.ts, apps/cms/src/server/fn/admin.ts)
- two-factor-and-step-up and rate-limits: Sign-in two-factor endpoint limit comes from the Better Auth library (3 requests per 10 seconds on /two-factor/*, default rateLimit enabled in production, memory storage). Confirm in a running instance (evidence: node_modules better-auth two-factor plugin index.mjs, better-auth dist/context/create-context.mjs)
- rate-limits: The research note 05 says the 60/min limit applies to POST /api/auth/*, but the code exempts /api/auth entirely. The page follows the code (evidence: apps/cms/src/server/http/rate-limit.ts enforceRequestRateLimit)
- rate-limits: Whether the AI limit response carries a Retry-After header, and the exact JSON shape of a server-function error response; the page avoids both (evidence: apps/cms/src/server/fn/ai.ts, apps/cms/src/server/ai/seo-generate.ts AiGenerationError, apps/cms/src/server/http/safe-error.ts)
- tokens: Invitation tokens are stored in plain text and shown to owners as copyable links; whether an accepted invitation token is single-use in every path is not documented (evidence: apps/cms/src/server/admin/members.ts, apps/cms/src/server/fn/me.ts acceptInvitationFn)
- tokens: The per-site preview secret is stored unhashed in the database and no screen rotates it, so a leaked preview secret cannot be replaced from the UI (evidence: apps/cms/src/db/schema.ts previewSecret, apps/cms/src/server/admin/sites.ts). Decide whether a rotation control is needed
- secrets: Whether the organization export bundle includes the DOKPLOY_CREDENTIALS_ENCRYPTION_KEY itself. Page states it does not, based on the export table list and the import requirement that the destination uses the same key. Research note 03 says both (evidence: apps/cms/scripts/authoring-transfer.mjs tables list, docker/RECOVERY.md)
- secrets: The claim that Better Auth two-factor secrets are protected with BETTER_AUTH_SECRET comes from docs/DEPLOYMENT.md, not from checking the library source (evidence: docs/DEPLOYMENT.md rotation section, better-auth dist)
- permissions-matrix: updateSiteFn is agency-only with no step-up, yet it sets the production URL and the deployment target. Confirm whether this is intended (evidence: apps/cms/src/server/security/authz-matrix.ts updateSiteFn, research note 03 section 8)
- ai-data-handling: No per-client or per-site switch to turn AI off; the only instance-wide off switches are removing the key or unsetting AI_SETTINGS_ENCRYPTION_KEY. Confirm this is intended (evidence: apps/cms/src/server/ai/settings.ts, apps/cms/src/server/fn/ai.ts)
- ai-data-handling: Whether editors see the AI actions when the saved key can no longer be decrypted (the code reports AI as enabled but generation fails with "AI is not set up yet"). The page says editors still see the actions. Confirm in a running instance (evidence: apps/cms/src/server/ai/settings.ts isAiEnabled, loadAiRuntimeConfig)
