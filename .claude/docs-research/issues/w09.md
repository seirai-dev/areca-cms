# Writer w09 issues (self-hosting: authentication, storage-and-email, deployment-targets, operations, publishing-pipeline)

- deployment-targets / publishing-pipeline: the admin UI string `settings_deploy_off` ("Not deploying. Going live marks the release as live.") suggests a site without a Dokploy target can go live without deploying, but the publish request rejects production sites that lack a target and health URL. Page documents the code behaviour. Owner of the CMS UI copy should confirm which is intended (evidence: apps/cms/messages/en.json:1119, apps/cms/src/server/publishing/publications.ts:150-165).
- storage-and-email / asset-retention: DEPLOYMENT.md says deleting an asset is "the only way" to stop a URL working, while ASSET_RETENTION.md says referenced assets cannot be deleted. The storage page avoids both claims and only says assets stay while referenced. Asset-retention writer needs the definitive answer (evidence: docs/DEPLOYMENT.md, docs/ASSET_RETENTION.md, apps/cms/src/server/assets).
- storage-and-email: the invitation email adapter sets no SMTP timeout (apps/cms/src/adapters/email/index.ts), but INTEGRATIONS.md says sending is "bounded by timeouts". The page does not claim a bound. Confirm whether a timeout is intended (evidence: docs/INTEGRATIONS.md section 3.3).
- operations / configuration: `LOG_LEVEL` is read directly from process.env in apps/cms/src/server/log.ts and is not in apps/cms/src/env.ts, so it is not validated at startup. Configuration page should say so or the code should validate it (evidence: apps/cms/src/server/log.ts:228).
- configuration: `ALLOW_PRIVATE_HEALTH_CHECKS`, `ADMIN_MFA_REQUIRED`, `WORKER_ENABLED`, `RATE_LIMIT_TRUST_PROXY`, `SETUP_TOKEN` and `DOKPLOY_ALLOW_INSECURE_HTTP` are missing from the OPERATIONS.md env table. The pages link to configuration for them (evidence: docs/OPERATIONS.md, apps/cms/src/env.ts).
- publishing-pipeline / troubleshooting: docs say a stale job is recovered after 30 minutes (apps/cms/src/server/publishing/worker.ts STALE_JOB_MS), but the code recovers a job as soon as its 60-second lease expires; the 30-minute value only applies to jobs with no lease. The page documents lease expiry. Troubleshooting writer should not repeat the 30-minute figure (evidence: apps/cms/src/server/publishing/worker.ts:52, 777-800).
- authentication: the UI wording for invitation delivery status ("accepted by the SMTP server") comes from INTEGRATIONS.md and was not checked against the People screen strings. Storage page describes it generically (evidence: docs/INTEGRATIONS.md section 3.3, apps/cms/messages/en.json people_invite_*).
- deployment-targets: `dokploy:setup` script behaviour (idempotent, creates app, writes build args) is described only as "onboarding". The required env list was taken from the script header (apps/cms/scripts/dokploy-setup.ts); not verified against a live Dokploy.
