The CMS reads its settings from environment variables. In the Docker deployment, you set most of them in `docker/.env`, and the Compose file passes them to the CMS container. This page lists every variable the CMS reads, grouped by purpose. Each table shows whether the variable is required, its default, and what it does.

Three rules apply to every table:

- **The Compose file passes only the variables it lists** to the CMS container. A variable that is not in the `cms` service's `environment` list has no effect, even when it is set in `.env`. Where a row says that the stock Compose file does not pass a variable, you must add it to the list before it takes effect. See [only listed variables reach the container](/docs/self-hosting/production#only-listed-variables-reach-the-container).
- **A blank value counts as unset in the validated CMS settings.** `KEY=` in `.env` uses the default, or fails the required check if there is no default.
- **Changes apply after a restart.** Run `docker compose up -d --wait` to recreate the container with the new values.

## Where values are loaded

For source development, use `apps/cms/.env.local`. The CMS loads `.env.local` then `.env` relative to its working directory; existing process variables win, then the first file wins. Plain dotenv does not expand `${OTHER_VARIABLE}` or run shell commands in values. Quote values containing `#` so they are not parsed as comments. Keep real env files out of Git.

For Docker, copy `docker/.env.example` to `docker/.env` and use `docker/compose.yml`. Compose interpolates this file; it does not forward its entire contents. For example, to enable a setting absent from the service's environment list, add it explicitly:

```yaml title="docker/compose.yml (cms service excerpt)"
services:
  cms:
    environment:
      RATE_LIMIT_TRUST_PROXY: ${RATE_LIMIT_TRUST_PROXY:-false}
```

Merge that entry into the existing mapping. Recreate the container after changes. `VITE_` settings are browser-exposed build inputs; never use that prefix for a secret. All CMS variables below are server-side unless marked otherwise. Website SDK settings belong in the website project, not the CMS container.

Every environment value starts as text. In the tables, **boolean** means the literal `true` or `false`, lowercase; **integer** means a decimal whole number without units; **URL** means an absolute URL including its scheme. A **provider credential** comes from that service: do not replace it with a locally generated encryption key. **Base64 key** means a fresh, independent `openssl rand -base64 32` value, not a password or API token.

## Required secrets

Four values must be set before the CMS starts. The CMS checks them at startup, and the Compose file refuses to start without `POSTGRES_PASSWORD`, `BETTER_AUTH_SECRET`, `S3_SECRET_KEY` and `DOKPLOY_CREDENTIALS_ENCRYPTION_KEY`.

| Variable | Why it is required |
| --- | --- |
| `BETTER_AUTH_SECRET` | Nonempty random secret string; generate with `openssl rand -hex 32`. Signs sign-in sessions. |
| `DOKPLOY_CREDENTIALS_ENCRYPTION_KEY` | Encrypts saved Dokploy API keys. The CMS requires it even if you have not connected Dokploy yet. |
| `POSTGRES_PASSWORD` | Password for the database user. Compose only. |
| `S3_SECRET_KEY` | Secret key for the storage service. Required by both Compose and the CMS. |

`CLOUDFLARE_CREDENTIALS_ENCRYPTION_KEY` is optional. Set it if you connect Cloudflare. Without it the CMS still starts, but the Cloudflare card shows "Encryption key not set" and saving a Cloudflare token is disabled. See [Cloudflare](#cloudflare).

Generate each secret with `openssl`. Use `openssl rand -hex 32` for `BETTER_AUTH_SECRET`, and `openssl rand -base64 32` for the encryption keys:

```sh
openssl rand -hex 32       # BETTER_AUTH_SECRET
openssl rand -base64 32    # DOKPLOY_CREDENTIALS_ENCRYPTION_KEY
openssl rand -base64 32    # CLOUDFLARE_CREDENTIALS_ENCRYPTION_KEY, if you use Cloudflare
openssl rand -base64 32    # AI_SETTINGS_ENCRYPTION_KEY, if you use AI settings
openssl rand -base64 32    # SECRETS_ENCRYPTION_KEY, if you save an SMTP password in Agency › Mail
```

An encryption key must be the base64 encoding of exactly 32 bytes: 44 characters, ending in `=`. The CMS rejects any other format.

<Callout type="warn" title="Back up the encryption keys with the database">
`DOKPLOY_CREDENTIALS_ENCRYPTION_KEY`, `CLOUDFLARE_CREDENTIALS_ENCRYPTION_KEY` and `AI_SETTINGS_ENCRYPTION_KEY` are used to decrypt values stored in the database. There is no automatic re-encryption. If you change or lose a key, the saved values become unreadable, and you must enter them again. Keep each key with the matching database backup. See [backup and recovery](/docs/self-hosting/backup-and-recovery).
</Callout>

The `docker/.env.example` file leaves `BETTER_AUTH_SECRET` and `DOKPLOY_CREDENTIALS_ENCRYPTION_KEY` empty, so you must generate both. Compose stops with a message if they are missing.

In production (`NODE_ENV=production`), the CMS refuses to start unless these checks pass:

- `REDIS_URL` is set. Compose sets it for you. Outside Compose, set it yourself, for example `redis://redis:6379`.
- `BETTER_AUTH_SECRET` is a real value. The CMS refuses the example values: `change-me`, and any value starting with `replace-` or `replace_`. It tells you how to generate one, with `openssl rand -hex 32`.
- No encryption key is all zero bytes. Each one that is set (`DOKPLOY_CREDENTIALS_ENCRYPTION_KEY`, `CLOUDFLARE_CREDENTIALS_ENCRYPTION_KEY`, `SECRETS_ENCRYPTION_KEY`, `AI_SETTINGS_ENCRYPTION_KEY`) is refused if it decodes to 32 zero bytes, and the error names it. Generate each one with `openssl rand -base64 32`.

Uploaded files and branding images are stored in an S3-compatible bucket. The bucket is created at startup if it does not exist.

| Variable | Expected value | Required | Default | Meaning |
| --- | --- | --- | --- | --- |
| `S3_ENDPOINT` | URL | Yes | Compose: `http://rustfs:9000` | URL of the S3-compatible API. |
| `S3_REGION` | Region string, e.g. `us-east-1` | Yes | Compose: `us-east-1` | The bucket's region. Use the region your storage service gives you. |
| `S3_BUCKET` | Bucket name string | Yes | Compose: `areca` | A private bucket, dedicated to Areca or shared with a separate `S3_PREFIX`. |
| `S3_ACCESS_KEY` | Storage access ID string | Yes | Compose: `${S3_ACCESS_KEY:-areca-demo}` | Access key with access to the bucket. |
| `S3_SECRET_KEY` | Storage secret credential string | Yes | Compose: required from `.env` | Secret key for the access key. |
| `S3_PREFIX` | Relative slash-separated path, e.g. `sites/production` | No | Unset (bucket root) | Installation path such as `areca` or `sites/production`. | `S3_FORCE_PATH_STYLE` | Boolean | No | `false` | Set to `true` for path-style addressing, which MinIO and RustFS need. Compose sets it to `true`. Keep the default `false` for virtual-hosted endpoints. |

See [storage prefixes and migration](/docs/self-hosting/storage-and-email#use-a-shared-bucket) for validation, reset scope, permissions and moving existing objects. Use the same prefix for every CMS process and maintenance script. Database keys, bundle keys and public URLs do not change.

## Email

The CMS sends email through an SMTP server. It sends invitations, password reset and email verification links, and security notices. The sender's display name comes from **Agency** > **Branding**.

You can set the mail server in two places: in these variables, or in **Agency** > **Mail** after you sign in. Settings saved in **Agency** > **Mail** replace these variables entirely. Turn on **Use environment settings** in that tab to send with these variables again. See [agency mail](/docs/cms/agency-mail).

Environment mail needs `SMTP_HOST`, `SMTP_PORT` and `SMTP_FROM` together; omitting any of them disables that source. The CMS starts without any SMTP settings. Until you set a server in one of the two places, mail is off. Invitations still work, and you can share a link with **Regenerate link** on the pending invitation.

| Variable | Expected value | Required | Default | Meaning |
| --- | --- | --- | --- | --- |
| `SMTP_HOST` | Hostname or IP, without scheme or port | No | Compose: `mailpit` | Hostname of your mail server. Compose points it at the Mailpit test inbox, which does not deliver mail. |
| `SMTP_PORT` | Integer port, 1–65535 | No | Compose: `1025` | Port of your mail server. Use `465` with `tls`, or `587` with `starttls`. |
| `SMTP_FROM` | Mailbox string, e.g. `cms@example.com` | No | Compose: `cms@areca.local` | The sender address. Use an address on a domain you have verified with your provider. Sending needs a From address, set here or in **Agency** > **Mail**. |
| `SMTP_USER` | SMTP username string | No | Unset | Username for SMTP sign-in. Leave it unset if your server does not need one. |
| `SMTP_PASSWORD` | SMTP password or provider app password string | No | Unset | Password for SMTP sign-in. It is kept in the environment file, so protect that file. |
| `SMTP_SECURE` | Enum: `starttls`, `tls`, `none` | No | `starttls`, or `none` for a localhost or private-network host | How the connection is secured. `starttls` is required on the connection (usually port `587`). `tls` uses TLS from the start (usually port `465`). `none` sends without encryption, and is allowed only for localhost and private-network hosts such as Mailpit. |
| `SMTP_REPLY_TO` | Mailbox string, e.g. `cms@example.com` | No | Unset | The reply-to address on outgoing email. |
| `SECRETS_ENCRYPTION_KEY` | Base64 key (32 bytes) | No | Unset | Base64-encoded 32-byte key that encrypts the SMTP password saved in **Agency** > **Mail**. It also encrypts the reset token kept in the email queue. If it is unset, the CMS uses `AI_SETTINGS_ENCRYPTION_KEY`. Without either key, you cannot save a password in **Agency** > **Mail**, and reset emails are not retried. If you change the key, enter the SMTP password again. |

The CMS always checks the mail server's certificate. Each connection, greeting and socket has a 15-second timeout.

The stock Compose file passes all of these mail variables to the CMS container. When `SMTP_HOST` is unset it falls back to the bundled Mailpit.

Use a mail server on your private network, or a transactional email provider, and do not expose an open relay to the internet. For provider settings and how to make your mail arrive, see [storage and email](/docs/self-hosting/storage-and-email).

## Website SDK variables

These belong in the consuming website's server/build environment. The CLI loads `.env.local` then `.env`; direct SDK calls read the process environment, so your framework or entrypoint must load it. See [SDK installation](/docs/sdk/installation).

| `ARECA_WRITES_STOPPED` | Literal `1` | Required acknowledgement for authoring transfer that every writer has stopped; it does not acquire a lock. |

| `E2E_PORT` | Integer port | Isolated E2E server; `3100`. |
