Now the editors' part. You write two posts in the CMS, approve them, and publish them.

## Know the three states

Every post has a status. Read this table once. It explains the words you will see.

| Status | What it means | Is it public? |
| --- | --- | --- |
| **Draft** | The latest saved version. Only the CMS shows it. | No |
| **Ready** | An owner approved this version. It goes live with the next Go live. | Not yet |
| **Live** | This version is on the website now. | Yes |

Saving a draft never changes the website. Only **Go live** does.

## 5.1 Write the first post

<Steps>
<Step>

**Open Posts.** In the site's sidebar, select **Posts**, then select **New entry**.

</Step>
<Step>

**Fill in the title.** Type `Our sourdough starter turns ten`. Check the **Slug** field. It should read `our-sourdough-starter`. The slug becomes the web address.

</Step>
<Step>

**Write the excerpt.** Type one or two sentences, for example: `Ten years ago we fed a jar of flour and water for the first time. Here is what it has taught us.`

</Step>
<Step>

**Add a cover image.** Select **Choose an image** in **Cover image**. Pick a picture from the Library, or upload one. Give the picture a description. Editors must describe pictures, because the description is the alt text that screen readers use.

</Step>
<Step>

**Write the body.** In the **Body** field, write two or three paragraphs. Add a heading and a short bulleted list, so you can see how formatting appears on the website.

![The Posts editor for the entry Our sourdough starter turns ten, with title, excerpt, cover image and body filled in](/screenshots/guide-entry-editor.png)

</Step>
</Steps>

The editor saves your changes as you type. The status stays **Draft**.

## 5.2 Write a second post

Repeat 5.1 with a second post. For example, the title `Three loaves for the weekend market`, with its own excerpt, picture and body. Two posts are enough to see a list on your website.

## 5.3 Mark both posts ready

Open the first post and select **Mark as ready**. Then do the same for the second post.

![Post in the Ready status, with the status card showing Ready to go live](/screenshots/guide-mark-ready.png)

Areca checks the required fields first. If a required field is empty, the post stays a draft and the editor says what is missing.

## 5.4 Go live

Open **Go live** from the site's sidebar. Under **What's changing** you should see both posts. Select **Go live**, then wait until the release shows as finished.

![Go live panel with both posts under What's changing and the Go live button](/screenshots/guide-go-live-panel.png)

You should now see both posts marked **Live** in the Posts list. Your website can now read them.

<Callout title="If something went wrong">
- **Mark as ready is greyed out.** You are an editor, not an owner. Ask an owner to mark the posts ready, or ask an admin to give you the owner role.
- **Go live is blocked.** The site may be in **Production** mode without a deployment set up. Ask your agency admin to finish the deployment settings, or ask them to switch the site to **Demo** mode for practice. In Demo mode a release is recorded but not deployed.
- **A post is missing from What's changing.** It was not marked ready. Mark it ready, then check the list again.
</Callout>
