This page lists what each role can do, one row per action. For a plain-language description of each role, read [roles and permissions](/docs/security/roles-and-permissions) first.

The columns are:

- **Editor**: a client editor.
- **Owner**: a client owner. Owners also have every editor action.
- **Admin**: an agency admin. Admins can act in every client, and have every action on this page.

Marks:

- ✓ the role can do this.
- – the role cannot do this.
- ✓ + step-up the role can do this, but only when its sign-in is recent. If it is not, Areca asks for an authenticator code first. See [two-factor authentication and step-up](/docs/security/two-factor-and-step-up).

Agency admins must also have two-factor authentication turned on. Without it, an admin is blocked from the actions in these tables. The exceptions are checking whether AI is available and the actions under **Your own account**, which an admin needs in order to turn two-factor on.

## AI apps and keys

These actions manage AI apps connected with OAuth, and personal AI keys, on the [Connect AI](/docs/cms/connect-ai) page. A connected app or key then acts as its user, and every tool it calls is checked against the same rules as the rest of this page. See [MCP endpoint and tools](/docs/cms/mcp-tools) for the tool list.

| Action | Editor | Owner | Admin |
| --- | :---: | :---: | :---: |
| Connect an AI app to a site by approving its consent screen | ✓ | ✓ | ✓ + fresh sign-in code |
| See your own connected apps | ✓ | ✓ | ✓ |
| See every connected app on a site | – | ✓ | ✓ |
| Disconnect your own connected app | ✓ | ✓ | ✓ |
| Disconnect someone else's connected app on a site | – | ✓ | ✓ |
| Allow a connected app to publish the site (consent checkbox) | – | ✓ | ✓ |
| Create a personal AI key for yourself | ✓ | ✓ | ✓ + fresh sign-in code |
| See your own AI keys | ✓ | ✓ | ✓ |
| See every AI key on a site | – | ✓ | ✓ |
| Revoke your own AI key | ✓ | ✓ | ✓ |
| Revoke someone else's AI key on a site | – | ✓ | ✓ |
| Allow an AI key to go live | – | ✓ | ✓ |
| Connect an AI app to the agency connector (every client and site) | – | – | ✓ + fresh sign-in code |
| Create a personal agency AI key (every client and site) | – | – | ✓ + fresh sign-in code |
| See and revoke your own agency AI keys and apps | – | – | ✓ |

A connected app or key allowed to publish can publish only while its user is still an owner or agency admin. A connection or key cannot do anything its user cannot do in the rest of this matrix. Approving a connection for a site needs a site role there, and the approval is for that site only. An agency connection or key reaches every client and site the admin can reach. It does not allow anything the admin cannot do in the CMS. Agency connections and keys end when the admin role ends. See [Agency connector](/docs/cms/agency-connector).

## Your own account

Every signed-in user can see their own profile, set up or turn off two-factor authentication, and accept an invitation with its link.

## Notes on "not found" answers

Some actions identify the object they act on by its ID, such as an entry, a site, a file, a build or an invitation. For those, a person outside the client gets the same "not found" answer as for an ID that does not exist. A person inside the client but without the required role gets "Forbidden", because they already know the object exists.

Actions that identify a client by its ID answer "Forbidden" to people who are not members, whether or not the client exists.

Revoking an AI key, or disconnecting a connected app, that belongs to someone else answers "not found" for editors, because editors can only see their own.
