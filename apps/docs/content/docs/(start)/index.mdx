Areca is a content management system built for agencies that run websites for their clients. Editors write and review content in the CMS. When it is approved, **Go live** freezes it into an immutable snapshot, and the website is rebuilt and deployed from that snapshot.

Your website stays a normal project in your own repository. The [site SDK](/docs/sdk) connects it to Areca: it pushes the content schema, pulls published content at build time, and renders rich text, SEO tags and draft previews.

![Posts list for Harbor & Pine Bakery with draft, ready and live entries](/screenshots/current-collection.png)

## How it fits together

A **client** is an organisation your agency works for. Each client has one or more **sites**. A site contains **collections**, which are content types such as Articles or Team members, and each collection contains **entries**.

<Steps>
<Step>

**Write a draft.** Saving a draft never changes the public website.

</Step>
<Step>

**Mark it as ready.** An owner approves a version for the next release.

</Step>
<Step>

**Go live.** Areca creates an immutable content snapshot, starts the website build, deploys it and runs a health check.

</Step>
<Step>

**The release becomes live** once the deployment is healthy. If something goes wrong, you can roll back to an earlier release.

</Step>
</Steps>

Read [How Areca works](/docs/concepts) for the full model.
